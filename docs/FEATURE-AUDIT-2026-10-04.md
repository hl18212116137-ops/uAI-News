# uAI News 功能取舍审查

日期：2026-10-04。范围：当前本地网页的访客体验、功能入口、相关组件与服务端实现。此次只新增审查记录和截图，没有删除功能或修改业务代码。

## 判断依据

以现有定位“AI 资讯聚合、订阅、中文阅读与解读”为依据，优先保留帮助用户发现、理解、保存资讯的能力。没有真实使用频率、留存率或成本账单，因此下文的价值和优先级是产品判断，不是用户行为统计。

结论：保留资讯阅读主流程，简化长文和个人偏好，把采集运营移到管理入口，删除没有实际效果的控制项及重复入口。保留现有白底、蓝色操作、金色解读、主内容列与侧栏布局。

## 建议保留

| 功能 | 建议 | 原因及边界 |
|---|---|---|
| 资讯流、中文标题和摘要、原文出处 | 核心保留 | 网站最直接的阅读价值；来源和发布时间有助于判断信息 |
| 来源订阅、取消订阅、来源筛选和搜索 | 核心保留 | 决定用户看什么；当前搜索仅针对信息源，不应描述成已有全文搜索入口 |
| 推荐信息源 | 保留于添加来源面板 | 帮助新用户完成首次订阅；无需再开一个推荐中心 |
| 主题分类 | 保留分类能力 | 窄屏可把行业、政策、观点线索放进“更多”；目前没有证据支持删除某个主题 |
| 按需 AI 解读、中文原文、要点 | 核心保留 | 与普通资讯列表形成差异；复用持久化结果，用户展开时读取或生成 |
| 收藏与收藏页 | 核心保留 | 阅读后保存的完整路径，维护成本相对明确 |
| 登录和账号 | 保留最小能力 | 当前订阅与收藏按用户隔离，不能为了少代码直接删除身份层 |
| 简单更新入口、更新状态和失败重试 | 保留 | 用户需要知道有没有新内容；普通界面不必暴露完整采集流程 |
| 内容去重、缓存、分页、请求取消、供应商接口 | 保留底层能力 | 是内容质量、性能和扩展能力的基础，不等于多余功能 |

## 建议精简或迁移

| 功能 | 具体取舍 | 原因 |
|---|---|---|
| PASS | 卡片保留“不感兴趣”；恢复记录放进偏好设置；采集淘汰原因给管理员 | 现在同一个 PASS 同时指用户反馈和机器筛选，概念混在一起 |
| 抓取与筛选设置 | 普通用户只保留时间范围、屏蔽词、优先词；抓取阈值、密钥状态、队列与错误日志移入管理界面 | 当前一个面板涵盖七步流程，阅读任务负担过重；组件当前为 1,861 行，维护面也较大 |
| 优质长文 | 保留精选列表、摘要、全文、原文链接；正文处理由服务端统一输出 | `LongformModule.tsx` 当前为 1,987 行，包含大量正文清理、摘要拼接与强调词计算；不应因此删除长文价值，但应收缩前端职责 |
| 自动长文处理 | 默认避免每轮抓取都同步做全文翻译；改成精选、按需或独立后台任务 | `lib/longform-auto.ts` 默认启用，每轮预算默认 4 篇；实际耗时和费用尚未测量 |
| 导入文章 | 优先保留受控的 URL 导入；文件上传先移到管理入口或暂停 | 它已经涉及全文提取、翻译、摘要和写库，超出日常阅读主任务；当前接口权限也需要先补齐 |
| 信息统计 | 缩为“订阅源数、近 24 小时新增”等可解释数据 | “专题”实际来自 `mediaCount`；“信息源”漏掉媒体；“近30天收录”在不同路径取当前 feed 数量或全库总数；“今日”实际是滚动 24 小时 |
| 访问时自动补抓 | 保留自动更新能力，移到统一调度 | `scheduleStaleSourceFetches` 从读取 feed 的路径触发，读取与采集副作用耦合；已有 30 分钟进程内冷却，但不是跨实例的统一任务控制 |

## 建议删除

1. **未执行的通用规则编辑器。** `plain_rule`、`disable_builtin_rule` 会写入数据库，面板据此显示自定义文字或隐藏默认说明；当前代码未将它们接入抓取、去重或 AI 处理。实际推荐处理仅消费时间范围、屏蔽词和优先词。不能让“删除默认规则”的界面效果被误认为运行规则已关闭。证据：`components/FetchPipelinePanel.tsx:312`、`lib/user-pipeline-rules.ts:179`、`app/api/me/pipeline-rules/route.ts`，以及全项目引用检索。
2. **顶栏 PASS 审核快捷入口和重复 PASS 明细展示。** 同一类记录同时出现于独立审核面板和抓取设置内。保留一处恢复入口及底层反馈数据即可，不删除用户历史。
3. **添加来源弹窗的拖动能力。** 对提交来源没有必要，另维护位置、拖动监听和边界计算；使用统一居中弹窗即可，现有外观可保持。
4. **长文目录的自由拖动。** 保留普通目录导航，去掉拖拽位置状态。此项为代码审查建议，当前数据库故障下未能验证真实长文目录。
5. **无对应产品机制的“专业版”标识。** `AnalysisPanel.tsx:1104` 为固定文本，没有依据账号等级切换；应删除，或在确有版本机制时再引入。
6. **普通页面的开发诊断文案。** 包括 `/api/health/feed`、环境变量设置提示、英文错误信息。后台诊断接口可保留，用户页面用明确的服务状态和恢复操作。
7. **生产解读服务里的硬编码示例答案。** `lib/services/analysis-service.ts` 内 `SEED_INSIGHTS` 对 `seed-*` 直接返回预写答案；当前 feed 已排除这类 seed 内容。将示例移至测试或显式开发演示模式，保持测试样本用途。

## 需先处理的功能问题

- **空白页面的提示与真实状态不符。** 当前首页持续显示“已触发后台抓取…通常 1–3 分钟内有内容”，而本轮 `/api/health/feed` 返回 `ok: false`，数据库检查失败。`EmptyState.tsx` 按空列表/来源状态组织文案，没有验证该任务正在成功运行。应区分没有内容、抓取进行中、服务不可用；不能让用户无期限等待。
- **匿名导入能力需要收紧。** `app/api/longform/import/route.ts:12` 没有会话校验；`middleware.ts` 的匹配排除了 API。导入服务会调用 AI 并经 `persistLongformArticle` 写入公共新闻表。建议暂停匿名 URL/文件导入，明确管理员导入或个人资料权限后再开放。此项来自代码路径检查，没有实际提交文件、写库或调用付费 AI。
- **键盘弹窗行为不完整。** 实测添加信息源弹窗按 Escape 无变化，焦点仍在背景“添加信息源”按钮；共享 `AppModalShell` 也没有焦点捕获/恢复和 Escape 处理。保留弹窗功能时统一修复，不能仅凭 `aria-modal` 声明认为无障碍完备。

## 暂不直接删除的对象

- `/news/[id]` 网页详情目前没有找到网页内入口，但不能据此证明没有旧书签或外部链接。优先统一阅读组件；确认访问情况后再决定是否下线路由。
- `/api/import-from-url` 当前没有找到网页调用方，也缺少路由内鉴权。与长文导入能力重叠但服务对象不同，需先查外部客户端/脚本使用情况，再下线或合并；不能把“没有 UI 入口”当成“没有调用者”。
- 独立 `mobile-app/`、第三个 AI 供应商适配器、RSS 和学术来源能力，不因当前访客首页没有内容就删除。是否保留这些产品方向，需要真实使用信息。
- 旧规则记录、PASS 历史和新闻数据不在“删除入口”的范围内，不应联动清空数据库。

## 建议实施顺序

1. 先修复数据库可用性及失败状态，关闭匿名公共导入，删除未生效的规则编辑入口。
2. 精简顶栏与统计，将 PASS 和真实偏好合并至设置，将运维流程移至管理入口。
3. 保留按需解读与长文阅读，移除拖动等附加交互，将全文加工与自动采集移到统一服务和后台任务。
4. 在可用数据库环境中验证订阅 → 更新 → 阅读 → 解读 → 收藏 → 不感兴趣/恢复完整流程，再用实际使用频率与调用成本决定后续取舍。

此次不提供性能收益百分比，也不据截图宣称完整无障碍合规。
