## 本轮修复

1. **隐藏内容后分页漏项。** 原来仍使用隐藏前的 offset，服务端列表前移后下一条可能被跳过。隐藏成功后使分页游标失效，重新取得第一页并按 ID 合并；隐藏请求期间停止翻页。测试确认 28 条隐藏 1 条后，完整加载剩余 27 条且无重复。
2. **管理员看不到未订阅或已暂停的信息源。** 管理页原先读取个人订阅元数据，现在读取全站源列表，仅向客户端传递 ID、名称、开关三个字段。实测启用→暂停以及普通用户禁止访问。
3. **登录后跳转校验不完整。** 浏览器会把反斜杠等地址规范化成外站 URL。新增统一校验，拒绝外站、反斜杠及控制字符，保留合法站内路径、查询串与锚点。
4. **路由参数重复解码。** 框架已经解码参数，头像和长文详情再次解码使 `100%25` 请求返回 500。移除重复解码：头像正常返回 SVG，未知长文正确返回 404。
5. **接口异常误报。** 收藏的无效 JSON、null、空 ID 返回 400；文章被清理后的收藏返回 404，并避免暴露数据库错误。解读接口 null 请求返回 400。
6. **文章网页抓取缺少边界。** 新增公开 HTTP/HTTPS 地址校验、DNS 解析结果校验与连接地址固定、逐跳重验证、最多 5 次跳转、12 秒期限和 4MB HTML 上限。私有/环回/链路本地/保留地址、带凭据或非标准端口的 URL 被拒绝。没有新增依赖。直接读取 Node.js 官方公开网页验证正常 HTTPS 抓取；内网、DNS 变更、恶意跳转、超大响应由自动测试覆盖。
7. **缺失页面无法继续浏览。** 新增符合现有视觉风格的中文 404 和“返回首页”，新闻不存在时进入标准 not-found 流程。普通用户访问管理页仍使用 404 隐藏管理内容。
8. **冒烟测试预算仅适用于空首页。** 有内容的 12 条首屏 HTML 约 118–120kB，原 90kB 阈值会误报。调整到 180kB；资讯 API 30kB、长文列表 API 100kB 的预算不变。

没有改动主页面设计语言或布局；删除的是重复解码及被统一实现替换的抓取/跳转逻辑。

## 性能取样（不是线上性能指标）

本机隔离 PostgreSQL + Next.js 生产构建，每个路径连续 6 次 HTTP 请求，后 5 次取中位数。包含响应体读取，不包含浏览器渲染；缓存已经受前面巡查预热，首个样本也不等于冷启动。

| 路径 | 响应大小 | 首个样本 | 后 5 次中位数 |
| --- | ---: | ---: | ---: |
| 首页（匿名、有内容） | 117,696 bytes | 34ms | 9ms |
| 资讯列表 12 条 | 12,872 bytes | 2ms | 1ms |
| 长文预览 12 条 | 22,910 bytes | 5ms | 3ms |
| 单篇完整长文 | 3,946 bytes | 2ms | 2ms |

合成的 1000 条资讯去重 CPU 基准：旧算法 4998ms，新算法 6.33ms，结果集合一致。此数字只说明去重算法，不代表网站整体倍数、真实网络或线上延迟。
